# Self-hosting Homestead

This guide takes you from nothing to a running Homestead instance
configured with the modules you want. If you're a contributor working
on Homestead itself, the root [`README.md`](../README.md) covers the
in-repo workflow.

## What you're building

Two processes:

- **aepbase** — a Go binary that serves an AEP-compliant REST API backed
  by SQLite. Holds all your data.
- **Your Homestead app** — a Next.js app generated by
  `create-homestead-app` that talks to aepbase through a same-origin
  `/api/aep` proxy.

Each user-facing feature (gift cards, recipes, todos, …) is an opt-in
**module**. You pick which ones to ship by editing one file your scaffold
created: `homestead.config.ts`.

## Prerequisites

- Node.js 20+ and npm
- Go 1.22+ (for building aepbase)

## 1. Scaffold your instance

```bash
npx create-homestead-app my-home
cd my-home
```

That generates:

```
my-home/
├── package.json            # depends on @rambleraptor/homestead-{app,core,modules}
├── tsconfig.json           # extends @rambleraptor/homestead-app/tsconfig.base.json
├── next.config.ts          # one line: calls createNextConfig()
├── postcss.config.js       # one line: re-exports from the package
├── eslint.config.mjs       # one line: re-exports from the package
├── instrumentation.ts      # one line: re-exports register + onRequestError
├── homestead.config.ts     # ← THE file you edit
├── .env.example            # AEPBASE_*, VAPID_*, GEMINI_API_KEY
├── public/                 # PWA icons + service worker
└── app/                    # thin Next.js App Router stub tree (re-exports only)
```

Every file under `app/` is a one-line re-export from
`@rambleraptor/homestead-app`. The Next.js plumbing — layouts,
providers, the catch-all module router, API handlers, the
instrumentation hook — all lives in the package. The only file you
actually edit to configure your instance is `homestead.config.ts`.

## 2. Choose your modules

Open `homestead.config.ts`. It looks like this:

```ts
import {
  creditCardsModule, dashboardModule, gamesModule, giftCardsModule,
  groceriesModule, hsaModule, notificationsModule, peopleModule,
  recipesModule, todosModule,
} from '@rambleraptor/homestead-modules';
import type { HomesteadConfig } from '@rambleraptor/homestead-app/registry/config';

const config: HomesteadConfig = {
  modules: [
    dashboardModule, todosModule, giftCardsModule, groceriesModule,
    recipesModule, peopleModule, hsaModule, creditCardsModule,
    gamesModule, notificationsModule,
  ],
};

export default config;
```

To trim the instance down — say, you only want a todo list and groceries:

```ts
const config: HomesteadConfig = {
  modules: [
    dashboardModule,
    todosModule,
    groceriesModule,
  ],
};
```

The settings and superuser modules are always installed by the registry
and don't appear in this list. They cover account management and flag
management — surfaces the rest of the app depends on.

Removing a module hides it from the sidebar, makes its URLs 404, and
drops its dashboard widget. The collections it owned are no longer
applied on the next Next.js boot — old data still lives in aepbase
(deleting a resource definition is destructive and isn't done
automatically), but new writes will 404.

## 3. Bootstrap the backend

aepbase ships as a separate binary you build once. From a sibling
directory:

```bash
git clone https://github.com/rambleraptor/homestead.git
cd homestead/aepbase
./install.sh           # first time only — builds bin/aepbase
./run.sh               # serves on :8090
```

aepbase prints the superuser email + password to stdout on first
start. **Save these credentials** — copy `my-home/.env.example` to
`my-home/.env.local` and fill in `AEPBASE_ADMIN_EMAIL` and
`AEPBASE_ADMIN_PASSWORD` so the schema sync runs automatically when
the Next.js server starts. The schema is applied once at boot — no
separate `apply` step is needed.

## 4. Run your instance

In a separate terminal:

```bash
cd my-home
npm run dev
```

Open http://localhost:3000 and log in with the superuser credentials
from step 3. `/` redirects to the dashboard; the sidebar shows
whichever modules you kept in `homestead.config.ts`.

## 5. Add a custom module

Modules live in their own workspace package
(`@rambleraptor/homestead-modules`), but a module is just an object
that satisfies the `HomeModule` interface — you can declare one inline
in your consumer app and add it to `homestead.config.ts`. The minimum
is a config object and the components its routes render:

```ts
// my-home/modules/laundry.tsx
import { Shirt } from 'lucide-react';
import type { HomeModule } from '@rambleraptor/homestead-app/registry/types';

function LaundryHome() {
  return <div>Laundry coming soon.</div>;
}

export const laundryModule: HomeModule = {
  id: 'laundry',
  name: 'Laundry',
  description: 'Track loads and detergent inventory.',
  icon: Shirt,
  basePath: '/laundry',
  routes: [{ path: '', index: true, component: LaundryHome }],
  section: 'Home',
};
```

Then in `homestead.config.ts`:

```ts
import { laundryModule } from './modules/laundry';

const config: HomesteadConfig = {
  modules: [
    /* existing modules… */
    laundryModule,
  ],
};
```

If your module needs its own aepbase collection, add a `resources` array
to the module config — the Next.js boot hook applies the schema; restart
the dev server to pick up the change. For a more substantial module
that wants its own dashboard widget, omnibox adapter, or background
worker, see the
[main repo's module guide](https://github.com/rambleraptor/homestead/blob/main/docs/MODULE_GUIDE.md).

## 6. Production deployment

For a long-lived instance behind systemd (or Tailscale), see
[`deployment/README.md`](../deployment/README.md). The deployment
package builds the app, wires up systemd services for aepbase and
Next.js, and includes sample `.env.production` templates.

## Where things live

In a Homestead instance generated by `create-homestead-app`:

```
my-home/
├── homestead.config.ts        # ← the file you edit
├── app/                       # one-line re-exports — don't touch unless you need
│                              #   to add a custom route or override one
├── public/                    # PWA assets — replace these to rebrand
└── .env.local                 # AEPBASE_*, VAPID_*, GEMINI_API_KEY
```

Everything else — the App Router shell, the module registry, route
matching, gates, providers, API route handlers, the instrumentation
hook, the catch-all worker dispatcher — lives in
`@rambleraptor/homestead-app`, which your `package.json` lists as a
dependency. Modules ship from `@rambleraptor/homestead-modules`. Auth,
shared UI components, and the aepbase client live in
`@rambleraptor/homestead-core`.
